# day42 津波避難シミュレータ — SPEC

複数日のプロジェクトの1日目。起点は 2026-11-26 の講演ノート（構造計画研究所）と、同じ日のデイリーの手書きメモ「津波シミュレータ作ろ。架空の都市、人の点群データ、主要な道路を定義して、避難所に逃げる人の流れを」。
技術は **Julia + Agents.jl + GLMakie**（ユーザーが選んだ。どれも 100日チャレンジで初めて使う）。day42 はコードを全部 Claude が書く。

## day42 でできること

海沿いの架空の町（1.2 km × 0.8 km）で地震が起き、3000人が避難所（高台2か所・津波避難ビル3棟）へ歩いて逃げる。20分後に津波が海側から陸へ上がってくる。
**避難を始めるまでの遅れ**をスライダーで変え、助かった人・流された人の数がどう変わるかを見る。道の合流点で詰まり（渋滞）が生まれるのが見どころ。

## 単位

- 1マス = 10 m 四方。1ステップ = 10 秒。60分 = 360ステップ。
- 歩く速さはマス/ステップで持つ（1.0 マス/ステップ = 1 m/s）。

## 町（src/city.jl）

格子は W=120 × H=80。y=1 が南（海側）、y=80 が北（山側）。Makie の heatmap は y が上向きなので、画面の下が海になる。

| 区分 | 場所 | 歩けるか |
|---|---|---|
| 海 | y ≤ 5 | × |
| 砂浜 | y = 6〜7 | × |
| 道 | 下の表 | ○ |
| 街区（家） | 道以外の y = 8〜66 | × |
| 高台（避難所） | 北の丘2つ | ○ |
| 津波避難ビル（避難所） | 3棟、各3×3マス | ○ |

道：
- 横の道：y = 8（海沿い）, 18, 28, 38, 50, 62, 66
- 縦の道：x = 4, 16, 28, 40, 52, 76, 88, 100, 112 は y = 8〜62。
- 大通り：x = 63〜65（幅3）、y = 8〜66。
- 丘へ上がれる道は限る（ここが詰まりの元）：x = 16 と x = 28 は y = 62〜70 まで延ばして高台Aへ。x = 100 は y = 62〜70 まで延ばして高台Bへ。大通りは y = 66 の横道につながり、y = 66 の横道（x = 16〜100）が両方の丘へ通じる。
- それ以外の縦の道は y = 62 で止まる。

避難所：
- 高台A：x = 12〜34, y = 70〜78 の範囲（全マス歩ける）。定員 1500。
- 高台B：x = 94〜110, y = 70〜78。定員 1500。
- 津波避難ビル：左下の角が (41, 19), (77, 19), (101, 29) の 3×3。道に接するように置く。定員は各 120。高さ 15 m（day42 では浸水深がこれを超えないので常に安全。値だけ持つ）。

標高 `elev[x,y]`（m）：
- 海は −5。陸は `0.12 * (y - 5)`（y=62 で約 6.8 m）。
- 高台A・Bの範囲は 20 m 以上になるよう、丘の中心からのガウス型の盛り上がりを足す（中心 (23, 75) と (102, 75)、高さ +18 m、幅 σ = 8 マス）。

歩けるマスの集合 `walkable::BitMatrix` を作る。

## 距離の場（src/city.jl）

避難所ごとに、歩けるマスの上で 8近傍の幅優先探索（BFS）をして「その避難所までの歩数」を持つ `dist[k]::Matrix{Int}`（届かないマスは typemax(Int)）。
人は「いまのマスより距離が小さい隣のマス」へ進むだけで避難所に着く（歩行者の流れのモデルでいう静的フロアフィールド）。経路探索（A*）は使わない。

## 津波（src/tsunami.jl）

- 到達時刻 `t_arrive` = 20分（120ステップ）。
- 海岸での高さ `H(t)`：到達前は 0、到達から 5分（30ステップ）で `H_max` = 8 m まで直線で上がり、その後は一定。
- 陸に上がると弱まる：マスの水位 `L(x,y,t) = H(t) - 0.02 * (y - 5)`。
- 浸水の広がり：海のマスから始め、毎ステップ、浸水済みのマスから 8近傍で `elev < L` のマスへ **最大 `front_speed` = 2 マス**（BFS の2層）だけ広がる。海とつながっていない低地は浸水しない。
- 浸水深 `depth[x,y] = L - elev`（浸水していないマスは 0）。
- 浸水深が `caught_depth` = 0.5 m 以上のマスにいる人は「流された」。

## 人（src/model.jl と src/rules.jl）

```julia
@agent struct Person(GridAgent{2})
    state::Symbol      # :waiting / :evacuating / :caught
    u::Float64         # 0〜1 の一様乱数。避難を始める時刻 = u * 2 * 遅れ
    speed::Float64     # マス/ステップ
    progress::Float64  # 速さの端数をためる
    target::Int        # 目指す避難所の番号
    elderly::Bool
end
```

- 人数 `n_people` = 3000。y = 8〜62 の道のマスにランダムに置く。
- 高齢者の割合 0.25。速さは高齢者 0.5、それ以外は 1.0〜1.3 の一様乱数。
- 避難を始める時刻 = `u * 2 * delay_steps`（`delay_steps` はモデルの値。スライダーで動かすと、まだ動いていない人の開始時刻がその場で変わる）。平均の遅れ `delay_min` = 10分。
- 目指す避難所 = 定員に空きがある避難所のうち、`dist[k][pos]` が最小のもの。

### 1ステップのルール（src/rules.jl の `person_step!`。後で差し替えやすいように、このファイルにはこの関数と補助関数だけを置く）

1. `:caught` なら何もしない。
2. いるマスの浸水深が `caught_depth` 以上なら `:caught` にして終わり。
3. 時刻が開始時刻より前なら `:waiting` のまま。
4. `:evacuating` にする。`progress += speed`。`progress ≥ 1` の間、次をくり返す：
   - 目指す避難所が満員なら、空きのある避難所のうち最も近いものに目標を変える。
   - 8近傍の歩けるマスのうち、`dist[target]` がいまより小さく、かついる人数が `cell_cap`（= 4）未満のマスを集め、距離が最小のもの（同点はランダム）へ動く。`progress -= 1`。
   - 動けるマスが無ければ、その場で待つ（詰まり）。`progress` は 1 未満に切り詰めて抜ける。
   - 避難所のマスに着いたら、その避難所の利用数を1増やし、モデルから取り除く（`n_safe += 1`）。
- 1マスの人数を数えるときは `:caught` の人を数えない。
- 並び順の偏りを避けるため、スケジューラはランダム順（`Schedulers.Randomly()`）。

## モデル（src/model.jl）

- `GridSpace((120, 80); periodic = false, metric = :chebyshev)`
- プロパティ：`t`, `delay_min`（スライダー用、分）, `cell_cap`, `elev`, `walkable`, `dist`, `shelters`（各避難所の名前・マス・定員・利用数）, `flooded::BitMatrix`, `depth::Matrix{Float64}`, `n_safe`, `n_caught`, 定義の値。
- `model_step!`：`t += 1` して津波を1ステップ進める。
- 集計：助かった `n_safe`、流された `n_caught`、まだ逃げている（`:waiting` と `:evacuating`）。

## 画面（run.jl と src/view.jl）

`julia --project=. run.jl` で GLMakie のウィンドウを開く。Agents.jl の `abmexploration`（再生・一時停止・1ステップ・リセットのボタンが付く）を使う。

- 背景（静止）：標高で塗った陸（低い = 薄い黄緑、高い = 濃い緑）、道 = 灰、街区 = 暗い灰、海 = 紺、高台 = 明るい緑、避難ビル = 白枠。`static_preplot!` で一度だけ描く。
- 水：浸水深を青の濃さで重ねる。浸水していないマスは NaN にして透明にする。
- 人：待っている人 = 橙、逃げている人 = 白（高齢者は少し小さい薄紫）、流された人 = 赤い ×。
- スライダー：`delay_min`（0〜30分）、`cell_cap`（1〜8）。
- 時系列：助かった・流された・まだ逃げている人数。
- 題字に「地震から mm:ss ／ 津波到達 20:00」。
- 日本語の文字は `set_theme!(fonts = (; regular = "Hiragino Sans"))` で出す。出なければ英語の表示に切り替える。

`julia --project=. batch.jl` で画面なしに回す。

- 遅れ `delay_min` = 0, 5, 10, 15, 20 分 × 乱数の種 5 つ。各 360 ステップ（60分）。

## 実装メモ（day42）

SPEC から変えた点とその理由。

- **cell_cap の既定値を 4 → 6 に変更**（`src/defs.jl` の `CELL_CAP`）。4 のままだと、丘へ上がる 1 マス幅の道（x=16, 28, 100）が詰まり、遅れ 0 分でも 38% が流された（SPEC の「遅れ 0 分ではほとんど助かる」を満たさない）。6 で 21%、8 で 9%。cell_cap ごとの比較表は results.md の付録に載せた。スライダーは SPEC どおり 1〜8。
- **高台の標高**: ガウス型を足しただけでは範囲の端が 12 m 程度にしかならず「20 m 以上」を満たさないので、高台の範囲内は `max(標高, 20 m)` にそろえた。浸水（最大でも y=62 で 0.02 m）には影響しない。
- **Agents.jl の `static_preplot!` は v7 に無い**。代わりに `preplot!(ax, abmobs)`（ヒートマップの後・人の前に呼ばれる）を使った。背景・避難ビルの枠・ラベル・凡例もここで描く。水の重ね描きは `heatarray` ではなく、`preplot!` の中で `lift(…, abmobs.model)` した `heatmap!` にした（`heatarray` だと背景より先に描かれて隠れるため）。
- **`agents_first = false`**（モデルの更新 = 津波を先に進めてから人が動く）。
- **1マスの人数は行列 `occ`** で持つ（`ids_in_position` を毎回数えるより速い）。`:caught`・避難済みの人は数えない。移動・流された・避難所に着いたときに `rules.jl` が更新する。
- 満員の避難所のマスには、目標でなくても入らない（入れる状態の避難所のマスにだけ入る）。
- 浸水深は海のマスでは 0（陸のマスだけ持つ）。
- batch.jl の results.md は、SPEC の列に「詰まりで待った延べ（人・ステップ）」の列と、cell_cap 別の付録表を足した。種は 5 つのまま（全体で約 15 秒）。
- 日本語表示: `Hiragino Sans` で出た。ただしタイトルは bold フォントを使うので、`fonts` に regular だけでなく bold・italic・bold_italic も同じフォントで指定しないとエラーになる。
- 画面の更新: `params`（スライダー）の値は「update」ボタンを押すとモデルへ反映される（Agents.jl の仕様）。
