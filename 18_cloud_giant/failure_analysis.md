# day18 雲の巨人: 失敗原因の分析(2026-11-13, Claude)

結論: 動かす仕組み(状態の混ぜ合わせ・天気・視線・顔追跡)はできた。失敗したのは「キャラクターの見た目」。原因は大きく3つ。

## 1. 目標の絵が最後まで1枚に決まらなかった

- 見た目の注文が言葉で来て、そのたびに目標が変わった: 「渋い顔」→ 人間の線画ラフ → ピンク → 夕焼けの写真。
- 線画ラフは**人間のおじさん**、写真は**光と影でできた雲の顔**。どちらも「雲のおじさん」そのものの絵ではない。
  「人間の顔を雲に置き換えるとどう見えるか」という一番難しい翻訳を、毎回 Claude がその場で決めていた。
- okimochi.md にあるとおり、Gemini に描かせたのは人間のおじさん。雲のおじさんのラフは最後まで無かった。

## 2. 作り方が、目標の絵と合っていなかった

- 今の作り方は「ぼかした丸(雲粒)を約250個重ね、2Dの線や影を上に描く」。
- ラフの魅力は**線**、写真の魅力は**大きな面の光と影**。丸い粒はどちらも苦手。
  - 線を足すと雲に貼ったシールになる(11-13 の1回目)。
  - 線を消して粒だけにすると、数が足りず顔の面(眉の張り出し・鼻の面)が作れない。
- 写真の雲が顔に見えるのは、無数の細かい盛り上がりと、本物の光(体積のある雲に夕日が当たる)があるから。
  粒ごとに疑似の光をのせても、面としての明暗にならない。11-13 最後の「顔の左半分を暗く」は、それを大きな影の塗りで後から足したもの。
- 「雲らしさ」と「顔の読みやすさ」は綱引きになる。どこで釣り合わせるかを決めないまま、行ったり来たりした。

## 3. Claude の進め方の問題

- **読み違い**: 「写真をこれに大幅に変えて」を風景ごと変える意味に取った。何を写真に寄せるのか(顔の立体感か、色か、風景か)を確かめずに大改造した。1往復まるごと無駄にした。
- **一度に変えすぎた**: 毎回、色・形・影・毛・口をまとめて変えたので、どこが良くなってどこが悪くなったかが分かりにくい。
- **自分の確認が甘かった**: 縮小したスクリーンショットを見て「直った」と報告していた。報告の時点で、ユーザーの「いい感じ」と比べられていなかった。
- **見比べる材料を出さなかった**: 1案ずつ実装して見せた。何案か並べて選んでもらう形にしていない。
- **確認に時間がかかった**: 画面を撮るのに1回1〜2分かかり、細かく試す回数が減った。

## できたこと(使い回せる部分)

- 表情・天気をキー長押しで連続的に混ぜる仕組み。
- MediaPipe の顔追跡で、まばたき・口・眉・視線・頭の向きをキャラクターの数値に流す部分。
- 雲粒を数値で膨らませ、暗くし、うねらせる部分(膨らむ・雨雲・嵐)。
  → 見た目(絵)と動き(数値)が分かれているので、絵だけ差し替えればこの仕組みは生きる。

## 付記: 眉や口をどうやって認識しているか(okimochi の疑問)

- 使ったのは Google の MediaPipe「Face Landmarker」。大量の顔写真で学習済みのニューラルネットが2段階で動く。
  1. 顔の478点の立体座標(目の縁・眉・唇の輪郭など)を出す。
  2. その点の並びから、52種類の表情の強さ(`jawOpen` 口の開き、`browDownLeft` 左眉の下がり、`eyeBlinkRight` 右目の閉じ具合 など、0〜1)を出す。
- こちらのコードは、その数値を読んで巨人の `open` / `brow` / まぶたに流しているだけ(`readFace` 関数)。
- 壁を越えたのは学習済みモデルの側で、それがブラウザで動く形で無料配布されているから、さらっと使えた。
