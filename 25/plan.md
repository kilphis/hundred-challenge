# day25 計画 — 将棋と戦争の間(マルチコア)

## 芯(ユーザー)

- 将棋と戦争の間みたいなゲーム
- 複数の大将が歩兵を使って、相手の王将を狙いに行く
- マルチコア処理を意識する

## 決めること

各項目の「仮」は Claude の仮決め。書き換え・消し込み・メモはこのファイルに直接どうぞ。
「→」の後ろが空なら仮のまま進める。

### A. マルチコアとのつなげ方

- A1. 何をマルチコアで動かすか
  - 仮: **大将1人 = Worker(コア)1つ**。各大将が自分の部隊の動きを別々のコアで同時に考える
  - 他案: 大将ごとではなく盤面の領域ごとに分ける / 見た目の演出だけで実際の並列計算はしない
  - →
- A2. 大将どうしは相談できるか
  - 仮: **できない**。各大将は「今の盤面」だけ見て考え、味方の他の大将が何をするかは知らない(各コアが独立して動くのと同じ)。ぶつかったら盤面のほうで処理
  - →
- A3. マルチコアをプレイヤーに見せるか
  - 仮: **見せる**。画面横に「どのWorkerがいつ考えていたか」の帯グラフ、考えた時間、並列度(CPU時間合計 ÷ 実時間)
  - →
- A4. 並列と直列を切り替えて比べられるようにするか
  - 仮: **する**。「並列(大将ごとにWorker)」「直列(Worker1つで順番に)」「メインスレッド(画面が固まる)」の3つ
  - →
- A5. 「思考量」(1手で試す候補の数)をプレイヤーが変えられるか
  - 仮: **変えられる**。多いほど賢いが重い。直列だと遅くなるのが体感できる
  - →

### B. 盤と駒

- B1. 盤の広さ
  - 仮: **16×16 マス**
  - →
- B2. 駒の種類と数(片側)
  - 仮: **王将1・大将3・歩兵18(大将1人につき6)**
  - →
- B3. 駒の動き
  - 仮: 全員**周囲8マスに1マス**(または止まる)。王将は**動かない**
  - 他案: 将棋のように駒ごとに動ける方向が違う

- B4. 体力

### C. 進み方

- C1. ターン制かリアルタイムか
  - 仮: **全員同時に動く刻み(tick)制**。1tickごとに全大将が同時に考え、全駒が同時に動く。tickの速さはスライダー
  - 他案: 交互のターン制 / 完全リアルタイム
  - →
- C2. 同じマスに入ろうとしたら
  - 仮: **どちらも動けない**。すれ違い(入れ替わり)も不可
  - →
- C3. 戦闘
  - 仮: 動いた後、隣(8方向)に敵がいれば**全員同時に1ダメージ**。狙う相手は 王将 > 大将 > 歩兵、同じなら体力の少ない方
  - →
- C4. 勝ち負け
  - 仮: **相手の王将を倒したら勝ち**。同時なら引き分け
  - →

### D. 大将と歩兵

- D1. 指揮範囲
  - 仮: 歩兵は**自分の大将から4マス以内**にいようとする(離れると戻る)
  - →
- D2. 大将が倒れたら
  - 仮: その歩兵は**その場で止まる**(隣の敵とは戦う)
  - 他案: 近くの別の大将の部隊に入る / 逃げる
  - →
- D3. 大将の立ち位置
  - 仮: 歩兵より**後ろ**にいようとする。大将自身も戦える
  - →
- D4. 獲った駒を使えるか(将棋の持ち駒)
  - 仮: **使えない**
  - →

### E. プレイヤーの操作

- E1. プレイヤーは何をするか
  - 仮: **自軍(下・青)の大将3人に目標を出す**。大将をクリック → 盤のマスをクリックでそこへ向かわせる。右クリックで「自動」に戻す。歩兵の細かい動きは大将(AI)まかせ

  - →
- E2. 何も指示しない大将

  - →
- E3. 相手(上・赤)
  - 仮: **CPU**(大将3人とも自動)
  - →

## 実装で決めたこと(Claude 2026-11-14)

仮のまま進めた項目に加えて、作りながら決めたもの。

- 作り: Rust + macroquad のデスクトップ窓(G→Rust)。WASM だとスレッドが使いにくいので、ブラウザ版にはしていない。大将の思考は `std::thread` のスレッド6本(青3・赤3の大将に1本ずつ)。
- 起動: `cd 25 && cargo run --release`
- 王将の体力は 3→**8**。3 だと 14tick で落ちて早すぎた。
- 初期値: 思考量 **100,000**、tick 間隔 **500ms**。
- 「思考にかかった実時間」は、最後のスレッドが計算を終えた時刻で測る(画面が結果に気づいた時刻ではない)。
- 歩兵がいなくなった大将は、敵の隣に行くのを嫌う重みを 3倍→1倍に下げる(大将どうしでにらみ合ったまま動かなくなったため)。
- **60 tick 誰も傷つかなければ引き分け**(膠着対策)。
- 確認用の引数: `--bench`(直列と並列の思考時間)、`--sim`(CPU同士20局)、`--shot <png> <tick>`。

### 測った結果(10コアの Mac、`--bench`)

| 思考量 | 直列 ms/tick | 並列 ms/tick | 倍率 |
|---:|---:|---:|---:|
| 2,000 | 0.67 | 0.24 | 2.7x |
| 20,000 | 5.56 | 1.63 | 3.4x |
| 200,000 | 51.69 | 14.00 | 3.7x |

6本に分けても 6倍にならない。大将ごとに部隊の人数が違い、いちばん重い大将を待つため(画面右の帯グラフで長さの差が見える)。
CPU同士60局: 青24勝・赤20勝・引き分け16。決着は多くが 15〜25 tick。
