# day30 分岐予測器を外から測る(Apple M4)

講義(consys)で「このMacには何ビットの予測器が入っているか」を調べた。Apple は構造を公開していないので、
周期のある分岐パターンを流して、予測器がどこまで覚えられるかを実験で調べる。C + clang。

## 動かし方

```sh
cd 30
./run.sh        # 時間から予測ミスを推定(パスワード不要。誤差が大きい)
./run.sh pmc    # sudo でハードウェアカウンタを使い、予測ミスを実数で数える
```

結果の表は `result_P.txt`(高性能コア)と `result_E.txt`(高効率コア)、生データは `data.csv` に出る。

## 実験

| 実験 | パターン | 覚えられたら | 覚えられなかったら | 分かること |
|---|---|---|---|---|
| A 乱数パターン | 長さ n のランダムな T/N 列を繰り返す | ミス率 0% | 50% | 何分岐ぶんの列を丸暗記できるか(容量) |
| B ループ出口 | T を n-1 回のあと N を1回 | 1周期 0回 | 1周期 1回 | 何回目で抜けるかを数えられるか(履歴の長さ) |

## Claude が決めたこと(差し替え可)

- 測る分岐は `cbz` をインラインアセンブリで直接書いた。C の `if` だとコンパイラが分岐なしの命令(`csel`)に変えることがあるため。
- 高性能コアと高効率コアの振り分けは QoS で行う(`USER_INTERACTIVE` → 高性能コア、`BACKGROUND` → 高効率コア)。macOS ではコアを直接は指定できない。
- 1回の計測は 2^24 分岐。予熱のため1回流してから9回測り、最小値を採る。最初に 0.5 秒空回しして CPU のクロックを上げておく。
- 時間から推定するときは、「常に成立」と「完全な乱数(ミス率 50%)」の2点を基準にして、ミス1回あたりの時間を出す。
- 実験A は n = 2〜4,194,304(2^k と 1.5×2^k)。実験B は時間推定なら n ≤ 1024、カウンタなら n ≤ 8192 まで。

## 結果(時間から推定、2026-11-16)

**実験A(高性能コア)**: n = 32,768 までミス率は約 12% 以下で、ほぼ覚えられている。n = 49,152 から上がり始め、n = 262,144 で 44%、それより長いと乱数と変わらない(50%)。
→ ランダムな列を **数万分岐ぶん** 丸暗記できる。2ビットカウンタ1本(講義の基本形)では、周期2の T/N 交互すら当てられない。履歴を使う大きなテーブル(TAGE 系)がある裏付けになる。
**ミス1回の重さ**: 高性能コアで約 4.3〜4.9 ns(約 4.5 GHz なら 20 サイクル前後)。高効率コアでは約 9〜12 ns。
**高効率コア**: n = 4,096 程度までは覚えられるが、n = 8,192 から崩れる。容量は高性能コアの 1/8 くらい。測定値のばらつきが大きい。

**実験B**: 時間からの推定では読めなかった。1周期のミス1回の影響は 1/n に薄まり、n が数十を超えると 0.03 ns(0.1 サイクル程度)の差になって誤差に埋もれる。1周期のミスが 1 を超える(本来ありえない)行があるのもそのせい。`./run.sh pmc` で数え直す。

実験A でも、n が小さいところの 2〜10% は本当のミスではないかもしれない(成立・不成立で命令の流れ方が変わるぶんの時間差が混ざる)。これもカウンタで確かめる。
